# 故障排查

**简体中文** | [English](troubleshooting.md)

请先确认准确的开发板型号、固件文件名或源码版本、框架版本，以及第一个失败的操作。每次只改变一个
变量。请使用 ESP32-S3-Touch-AMOLED-1.75 专用的固件、分区和设置；名称相近的开发板也不能直接
共用二进制固件。

## 开发板无法进入下载模式

- 确认 USB 线支持数据传输，并且 USB 电源稳定。
- 关闭占用所选端口的其他串口监视器或应用程序。
- 断开并重新连接开发板，确认该端口会消失并重新出现。
- 如果自动复位失败，请按住 BOOT、短按 RESET，启动烧录命令，并在开始写入后松开 BOOT。
- 如果写入总在不同偏移处失败，或出现数据包/超时错误，请降低烧录波特率。

不要通过反复擦除 Flash 来排查端口问题；下载模式是否可用与 Flash 中存储的应用程序无关。

## Flash 布局、16 MB 镜像头与完整镜像

下面这类错误表示检测到的 Flash 大小与镜像头不一致：

```text
Detected size(16384k) smaller than the size in the binary image header(32768k)
```

请使用面向本开发板 16 MB Flash 布局的软件包。不要混用不同产物中的 Bootloader、分区表、
应用程序、ESP-SR 模型或文件系统。优先把包内 `*-combined.bin` 写入 `0x0`；工厂镜像是完整的
16 MiB 镜像，也必须从 `0x0` 开始写入。

擦除整片 Flash 不是常规第一步。只有在已经选择正确完整镜像，但明确已知旧的错误分区表或 32 MB
镜像仍然造成冲突时才考虑执行。下面的操作会删除 Flash 中的全部设置和内容；执行前请备份所需
数据并确认目标端口：

```bash
python -m esptool --chip esp32s3 --port PORT erase_flash
```

如果在上述特殊情况下执行了整片擦除，应立即烧录一份完整且相互匹配的合并镜像。不要在只有应用
程序二进制文件的情况下启动设备。

## 循环重启、看门狗或栈溢出

1. 确认开发板使用稳定电源，并断开可选扩展硬件。
2. 把匹配的完整镜像重新写入 `0x0`。
3. 记录启动信息，以及第一次 Panic、看门狗信息或回溯。后续重复出现的同一复位通常不会增加有效
   信息。
4. 对于源码构建，确认使用文档规定的 ESP-IDF 版本、工程自带的 `sdkconfig.defaults` 和分区表。
   在 ESP-IDF v6 下构建 ESP-Brookesia 示例时，请保留 `sdkconfig.defaults.v6`。

不要用其他开发板的副本单独替换 Brookesia、LVGL、BSP 或音频组件。显示锁、任务栈、音频所有权和
内存配置都与具体开发板和工程有关。

## 空白、白屏、局部刷新或显示损坏

- 确认固件面向本开发板的 466 × 466 CO5300 QSPI AMOLED。
- 烧录后复位一次，并使用稳定的 USB 电源。
- 烧录完整合并镜像，不要只烧录应用程序二进制文件。
- 不要混用其他显示屏或框架构建中的显示初始化、LVGL 配置、Cache/Flush 回调或 BSP 文件。
- 使用 `02_lvgl_demo_v9` 对比。如果该示例正常而 Brookesia 异常，请记录是哪个启动阶段或应用首次
  出现陈旧/空白区域。
- 如果只有触摸区域发生刷新，或者旧像素残留，请拍摄一张完整圆屏照片，并记录第一条相关显示/LVGL
  错误。反复点击可能会掩盖最初的刷新边界。

本 AMOLED 没有传统的 GPIO 控制 LCD 背光。因此，完全白屏或空白通常不能通过切换背光引脚解决；
应检查面板初始化、完整镜像、电源稳定性和显示 Flush 通路。

## 触摸无响应、偏移或间歇失效

- 运行 `10_Touch_CST9217`，确认触摸中断能产生原始坐标。该诊断示例有意不初始化显示屏或 LVGL。
- 清除屏幕上的水渍、保护膜气泡或导电物体，先测试单指，再测试双指。
- 如果原始诊断正常但 LVGL 应用异常，请保持随附的旋转和触摸变换成套使用；不要只改变某一个坐标
  轴、交换或镜像选项。
- 如果没有原始事件，请先检查 CST9217 复位/中断通路和共享 I2C 总线，再修改 UI 代码。

报告偏移时，请说明实际触摸的界面标志和报告的坐标；只说“触摸不对”不足以区分旋转、缩放和中断
丢失。

## Brookesia 加载或启动器启动

工厂固件会在开发板、存储、音频、状态服务和应用初始化期间显示分阶段加载画面。它应到达 `Ready`，
然后切换到完整的 466 × 466 启动器，不应出现 Panic、白屏或局部刷新画面。

如果停在某个阶段，请记录该阶段和紧邻的串口输出。首次安装 AIChats 时，请确保分区表、应用程序、
`srmodels.bin` 和 `storage.bin` 全部来自同一构建；随附工厂镜像已经将它们合并。对于源码构建，请
保留同步的本地 Brookesia 快照和依赖配置，不要单独更新一个组件。

## 电池、充电、状态栏或 Wi-Fi 状态

电池图标和百分比来自 AXP2101 电量计和充电状态。Wi-Fi 图标表示真实的 Station 连接和 RSSI，不是
只表示 Wi-Fi 开关是否打开。

- 未连接电池时，不应期待正常的电量百分比。请连接设计要求的电池，并在启动后等待电量计稳定。
- 如果电池、VBUS、温度或充电字段一直不可用，请先使用 `01_AXP2101` 或
  `05_LVGL_AXP2101_ADC_Data` 对比，再修改 Settings。
- 如果 Wi-Fi 已开启但图标仍显示未连接，请确认存在可访问的 2.4 GHz 接入点，在 Settings 中重新
  连接，并等待关联和获取 IP 完成。
- 如果关闭 Settings 后 Wi-Fi 本应保持开启，请重启一次，检查持久化开关和已保存网络是否会自动
  重连。常驻 Wi-Fi 服务设计为可在 Settings 页面之外运行。
- 如果图标不正确，请同时对比 Settings 详情（充电状态或 RSSI）与状态栏，并报告两处观察结果，
  不要只提供一个控件的截图。

请求帮助时不要公开 Wi-Fi 凭据或未经脱敏的扫描列表。

## AIChats 显示“Service unavailable”

“Service unavailable”可能来自网络可达性、激活/账户状态或远程 Xiaozhi 服务；仅凭这条提示不能
证明 ES8311/ES7210 硬件故障。

1. 确认状态栏和 Settings 显示真实 Wi-Fi 连接，而不只是开关已打开。
2. 确认设备已完成所需激活流程，并且配置的远程服务当前可用。
3. 测试语音输入/输出前关闭 MusicPlayer、VideoPlayer、SpecAnalyzer 和 Recorder，让 AIChats 能够
   获取共享音频服务。
4. 如果 WakeNet/模型初始化失败，请安装完整且匹配的工厂镜像；当 `srmodels.bin` 或存储内容可能
   缺失时，不要只烧录应用程序。
5. 区分传输故障和音频故障：远程服务已响应但没有声音，重点检查播放/音量；没有发起连接，重点
   检查 Wi-Fi 或激活；没有麦克风活动，重点检查音频所有权或采集初始化。

所有报告都必须删除激活码、Token、账户标识、对话文本和语音录音。

## MusicPlayer、ES8311、扬声器或 PA 无声

- 把真正的 MP3/WAV 文件放入 `/sdcard/music`（也兼容 `/sdcard/Music`）；只修改扩展名不会转换
  文件内容。
- 确认播放器已经列出文件、播放/暂停状态会变化、音量大于零，并且外接扬声器连接正确。
- 重新测试前关闭 VideoPlayer 和 AIChats。同一时间只能有一个应用拥有共享扬声器通路。
- 开发板播放通路使用 ES8311，PA 使能信号位于 GPIO46。BSP 音频服务应同时配置两者；不要永久
  强制打开 PA，也不要绕过其所有权/生命周期管理。
- 使用 Arduino `08_ES8311` 对比。如果该示例正常，排查工厂应用时应保留其开发板专用 I2S/Codec
  通路。
- 如果打开应用导致复位，请记录第一次 Panic/回溯以及紧邻它之前的日志。不要把无声、音频忙提示
  和重启当成同一种故障。

要进行可重复验证，请使用 [SD 卡素材制作指南](../firmware/MEDIA_GUIDE.md)规定的 WAV 配置和测试
素材。

## SpecAnalyzer、Recorder、ES7210 或麦克风异常

- 关闭 MusicPlayer、VideoPlayer 和 AIChats，确保采集通路没有被其他应用占用。
- SpecAnalyzer 和 Recorder 通过 ES7210 使用两个板载麦克风。依次靠近每个麦克风讲话，以区分单
  通道问题和整体采集失败。
- Recorder 应在 `/sdcard/Waveshare/Recordings` 下生成 24 kHz、16-bit 双声道 WAV。请正常停止
  录音并等待同步关闭完成后再拔卡。
- 异常断电或拔卡后可能留下 `.wav.partial`。请先备份，再按照素材指南中的命令恢复；不要直接将其
  重命名为 `.wav` 并假设文件头已经完成。
- 如果频谱一直为零且录音无声，请先检查 ES7210 初始化和音频所有权信息，再修改 FFT 或 UI 代码。
- 如果应用提示音频忙，请关闭当前所有者。应用不应抢占或释放其他应用的音频会话。

## microSD、Gallery、VideoPlayer 或 AVI 问题

- 使用 FAT 或 FAT32。当前固件不支持 exFAT 或 NTFS，并且挂载失败后不会自动格式化卡。
- 打开 **Settings > Storage** 检查容量/可用空间，运行 CRC 基准测试，重新插卡后执行 Rescan，并在
  物理拔卡前执行 **Safe eject**。
- Gallery 扫描 `/sdcard/photos` 下的基线 `.jpg`/`.jpeg`，最多索引 128 个文件，并拒绝大于
  4 MiB 的文件。不支持 Progressive JPEG。
- VideoPlayer 需要 `/sdcard/video` 下的 MJPEG（`MJPG`）AVI。推荐 320 × 240 或 360 × 360、
  10 fps；可选音频必须是支持采样率的 16-bit PCM，且为单声道或双声道。不支持 H.264/H.265
  视频，也不支持 AVI 中的 AAC/MP3/ADPCM 音频。
- 如果只显示视频控制界面而没有画面，请使用 `ffprobe` 检查流；把 MP4 改名为 `.avi` 不是格式
  转换。
- 如果播放卡顿，请使用 320 × 240、10 fps，减小单帧 JPEG，并先用随附的合成 AVI 测试，再判断
  是 SD 卡还是显示问题。

准确目录、FFmpeg 命令、`ffprobe` 检查、安全弹出行为和 Recorder 恢复方法见
[SD 卡素材制作指南](../firmware/MEDIA_GUIDE.md)。

## Arduino Core、开发板或库冲突

- 使用 Arduino-ESP32 `3.3.10`、ESP32-S3、16 MB Flash 和 `app3M_fat9M_16MB` 分区方案。
- 使用 `examples/arduino/libraries` 下的随附库。删除重复的全局副本，或确保随附路径优先。
- 阅读编译器的 “Multiple libraries were found” 输出，并在修改源码前确认实际选择的路径。
- 不要混用名称相近的其他 Waveshare 开发板的引脚定义或显示/音频库。
- 先构建一个未经修改的仓库示例。如果成功，再分小批恢复本地修改。

## 使用最少且脱敏的证据请求支持

请按照 [SUPPORT.md](../SUPPORT.md) 提交信息，并且只提供复现第一次故障所需的证据：

- 准确的开发板型号，以及连接的扩展硬件。
- 固件文件名或提交版本、框架/工具版本和烧录方式。
- 简短复现步骤、预期行为和实际行为。
- 启动信息，以及从最后一个正常阶段到第一条错误或回溯之间的最小日志片段。
- 只有在显示或连接状态差异难以用文字说明时，才附一张裁剪后的照片。

分享前必须删除 SSID、密码、IP 和 MAC 地址、设备 ID、UUID、激活码、Token、账户标识、对话文本、
录音内容/文件名、客户数据，以及本地用户名或文件路径。当较小的脱敏片段已经能说明问题时，不要上传
完整串口日志、Wi-Fi 扫描、诊断导出、SD 卡镜像或完整截图。
