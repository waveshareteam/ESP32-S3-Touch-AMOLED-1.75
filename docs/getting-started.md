# Getting Started

[简体中文](getting-started_ZH.md) | **English**

This guide covers release firmware, the complete factory image, ESP-IDF source builds, and Arduino
source builds for the ESP32-S3-Touch-AMOLED-1.75.

## Before You Start

You need:

- An ESP32-S3-Touch-AMOLED-1.75 board.
- A USB data cable and a stable USB power source.
- The serial port assigned to the board.
- Python 3 for prebuilt-firmware flashing.
- ESP-IDF or Arduino tools only when building from source.

Use firmware and settings intended for this exact board. The projects, release artifacts, and factory
image use a 16 MB flash layout. Do not mix bootloader, partition-table, application, model, or
filesystem binaries from different builds.

## Flash a Release Package

Release packages are generated by GitHub Actions from the tagged source revision. Each package is for
one example and one supported toolchain; it is not the same deliverable as the Brookesia factory image.

1. Open the [Releases page](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.75/releases).
2. Download the `*-combined.zip` for the required example and framework version.
3. Extract the archive.
4. Install esptool:

```bash
python -m pip install esptool
```

5. Flash the combined image.

Linux or macOS:

```bash
./flash_combined.sh /dev/ttyACM0
```

Windows:

```bat
flash_combined.bat COMx
```

Replace the example port with the port assigned to the board. The scripts write the combined binary
at `0x0`. The same archive also contains split binaries and `flash.sh` / `flash.bat` for
offset-based flashing; use one method from one archive rather than mixing the two methods.

If automatic reset cannot enter download mode, hold BOOT, tap RESET, start the flash command, and
release BOOT after writing begins.

## Flash the Factory Image

The customer factory image is
[`firmware/ESP32-S3-Touch-AMOLED-1.75-FactoryOnly-260805.bin`](../firmware/ESP32-S3-Touch-AMOLED-1.75-FactoryOnly-260805.bin).
It is a complete 16 MiB image written once at `0x0`. It combines the bootloader, partition table,
initial OTA data, ESP-SR model, Brookesia application, and SPIFFS filesystem.

From the repository root, replace `COMx` with the board port and run:

```powershell
python -m esptool --chip esp32s3 --port COMx --baud 460800 --before default_reset --after hard_reset write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m 0x0 .\firmware\ESP32-S3-Touch-AMOLED-1.75-FactoryOnly-260805.bin
```

A normal update does not require erasing the whole flash. See the bilingual
[firmware delivery guide](../firmware/README.md) for the published checksum, SD-card package, and
device-validation procedure.

## Build with ESP-IDF

Supported release branches are ESP-IDF `v5.5.4` and `v6.0.2`. Activate the selected ESP-IDF
environment, then build a project from the repository root:

```bash
idf.py -C examples/esp-idf/02_lvgl_demo_v9 \
  -B build/02_lvgl_demo_v9 \
  set-target esp32s3 build
```

Flash and monitor with the same build directory:

```bash
idf.py -C examples/esp-idf/02_lvgl_demo_v9 \
  -B build/02_lvgl_demo_v9 \
  -p PORT flash monitor
```

Managed dependencies are downloaded by the ESP-IDF component manager during configuration. The
ESP-Brookesia example has an additional `sdkconfig.defaults.v6` overlay for ESP-IDF v6; CI applies
that overlay automatically.

The customer Brookesia project under `firmware/brookesia` is maintained and validated with ESP-IDF
`v5.5.4`. Its first complete installation must include the application, partition table, ESP-SR
model, and storage image. Use the supplied complete factory image when a single-file installation is
preferred.

## Build with Arduino

The validated Arduino-ESP32 core is `3.3.10`. Use the ESP32-S3 board target with:

- Flash size: 16 MB.
- Partition scheme: `app3M_fat9M_16MB`.
- Bundled libraries: `examples/arduino/libraries`.

Arduino CLI example:

```bash
arduino-cli core install esp32:esp32@3.3.10

arduino-cli compile \
  --fqbn "esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB" \
  --libraries examples/arduino/libraries \
  examples/arduino/01_HelloWorld
```

In Arduino IDE, add the folders under `examples/arduino/libraries` to the sketchbook libraries or
use the bundled copies as the source of the required versions. Select the same flash size and
partition scheme before uploading. Remove or deprioritize duplicate global libraries if the IDE
selects an incompatible copy.

## Example-Specific Hardware

- `07_LVGL_SD_Test` requires a FAT/FAT32 microSD card.
- `08_ES8311` exercises the ES8311 playback path and external speaker connection.
- `09_LC76G_I2C` requires the `-G` variant or equivalent LC76G hardware connected over I2C.
- `10_Touch_CST9217` reports raw touch-controller coordinates over the serial monitor and
  intentionally does not initialize the display or LVGL.
- `04_Immersive_block` uses the QMI8658 IMU for motion input.
- `05_Spec_Analyzer` uses the two onboard microphones through ES7210.
