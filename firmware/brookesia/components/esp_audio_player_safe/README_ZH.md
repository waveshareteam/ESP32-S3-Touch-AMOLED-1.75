# ESP 音频播放器安全覆盖层

[English](README.md)

本目录内置 `chmorgan/esp-audio-player` 1.1.0，并由
[`../bsp_extra/idf_component.yml`](../bsp_extra/idf_component.yml) 通过
`override_path` 选用。公共组件版本和传统播放 API 继续兼容 1.1.0。通用 API 与
支持格式见随附的[上游 README](esp-audio-player/README.md)。

## 本地生命周期修复

该覆盖层使播放器删除流程具有确定性，确保应用在释放共享音频所有者或 SD 挂载
租约前，播放器已经完成清理：

- 完成信号量使删除任务能够等待音频工作任务确认关闭；确认后，工作任务不再访问
  实例存储。
- 删除门用于拒绝对同一个实例的并发删除。
- 关闭请求以有界等待插入队列前端，整个关闭过程最多等待五秒。如果工作任务未能
  及时停止，删除返回 `ESP_ERR_TIMEOUT`，并保留完整实例以便安全重试。
- 关闭成功后，清理逻辑会排空尚未处理的 PLAY 请求，并关闭所有已经转移给播放器、
  但工作任务尚未消费的 `FILE`。
- 只有实例删除成功后才会清空传统单例，因此失败的删除不会暴露已经释放或只完成
  一半清理的播放器。
- 音频工作任务不能通过回调删除自身；开始关闭后，新的控制事件也会被拒绝。

这些改动保留 `audio_player_play()` 规定的文件所有权规则：成功交接后，播放器
拥有并关闭 `FILE`；交接失败时，文件仍由调用者负责关闭。

## 调用者约束

必须等待 `audio_player_delete()` 返回 `ESP_OK`，然后才能关闭编解码器、释放
`bsp_extra` 音频所有者，或卸载包含正在播放或排队文件的存储设备。如果删除超时，
不要释放回调或依赖状态；应先解决停滞的工作任务，再重试删除。

该组件继续使用随附的 Apache License 2.0。更新内置源码时应保留嵌套的上游
README 和许可证，并在比较新上游生命周期行为后，明确地重新应用或移除本地改动。

[`../../HARDWARE_VALIDATION_ZH.md`](../../HARDWARE_VALIDATION_ZH.md) 中 MusicPlayer
快速进入/退出及跨应用音频所有权测试。UI 能正常退出还不够；串口输出中不得出现
超时、失效回调、跨所有者释放或 SD 租约持续占用。
